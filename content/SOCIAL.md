## LinkedIn (single post)

**Every on-call team relearns problems it has already solved.**

An alert fires at 2 a.m. The engineer has never seen this exact failure — but someone on
the team fixed it four months ago. That knowledge is trapped in a closed ticket and a
scrolled-away chat thread, so the new responder starts from zero. Mean-time-to-resolve pays
for it, every time.

I built **Muninn** for Hack with Hyderabad 3.0 to attack exactly this: an incident-response
copilot that treats institutional memory as a first-class system.

The demo is one toggle — Cold ⇄ Warm. With memory off, the copilot gives a generic,
un-cited guess. With memory on, the same model triages the same alert but now recalls
similar past incidents, names the root cause, recommends the specific fix that worked
before, and cites the incidents it learned from. Resolve it, and the outcome becomes memory
for the next responder. The longer it runs, the faster the team gets — and you can watch
the learning curve rise.

Memory is powered by Hindsight (Vectorize) — its retain / recall / reflect operations are
the heart of the system. It runs fully offline with a faithful local fallback, so it's a
one-command try.

All incident data in the demo is synthetic and clearly labeled; the metrics are computed
over that dataset, not mocked.

Would love feedback from anyone in SRE / platform / incident management. 🐦‍⬛
